# CS 个人 IP 口播

把一个亲历的项目、失败、现场观察或可核实结果，写成一条让观众相信“你确实做过、想明白了”的中文口播。默认面向 AI 创业、赚钱案例、产品构建和个人过程，交付 60–90 秒可直接录制的一稿。

## 输入与缺口

优先从用户已有素材中提取：发生在什么场景、自己做了什么、结果或证据是什么、因此得出了什么判断。每条只服务一个具体人群、场景和问题。

真实锚点不足时，只追问最小缺口；不要把推测补成亲历、数据、客户评价或案例。用户只给一个泛观点时，可以先帮助收敛为可讲的真实事件，不直接写成貌似亲历的故事。

## 从素材到成稿

默认使用下面的推进关系。它是节奏检查，不是把所有主题写成同一腔调的模板；时段均为预计参考。先确定这条内容承诺、可由材料支撑的结尾，再选择推进顺序：

1. **真实反常瞬间（0–8 秒）**：从具体损失、动作、冲突或反常结果进入，让目标观众立刻识别自己的处境。
2. **一句判断（8–18 秒）**：提出可争辩、可验证的个人判断，说明这条不是工具清单或空泛感想。
3. **证据与过程（18–55 秒）**：用项目过程、失败、取舍、数据或可核实案例证明判断。检查“因为—行动—结果—调整”是否成立；每段增加新事实、场景、解释或判断，不机械按固定秒数制造反转，不用同义句拖时长。
4. **可迁移动作（55–75 秒）**：把经历转译为观众今天能做的一步，给边界，不许诺万能结果。
5. **克制收束（75–90 秒）**：回扣开头并留下带条件的结论；默认不加 CTA。只有内容与用户的产品、资料或服务天然相关时，才加入一个明确动作。

## 交付格式

按用户需要直接交付成稿；默认包含：

1. **口播稿**：只含实际朗读文字，不把停顿、重音、镜头提示混进台词。
2. **演绎标注**：按上述五段给出计划时段、停顿、重音或表情/镜头建议。计划时段只是录制参考，不是最终音频时间轴。
3. **事实待确认项**：仅列会改变事实准确性的最小缺口；没有则写“无”。
4. **口播自检**：确认单一受众/场景/问题、真实锚点、判断可证、信息推进、可行动作、无虚构或 AI 套话、CTA 是否必要。

以可朗读字数和明确语速假设给出“预计”时长；最终音频才决定真实时码。需要多版本开头、仅给结构或更短/更长时，按用户要求调整，不默认生成多个标题党版本。

## 表达要求

- 先让人看见做事现场，再给判断；不以“AI 时代”“你有没有发现”或泛用金句开场。
- 保留犹豫、失败和限定条件。判断可以尖锐，但证据不能夸大。
- 用短段、自然口语和具体名词；每段有新的信息任务，不把一个结论换三种说法。
- “建议做什么”必须从前述事实推导，不把个人经验包装成人人适用的定律。

## 路由与边界

- 内容还没有真实项目或经历、需要先收敛选题与制作方案时，使用 `$cs-chatcut-video-blueprint`。
- 已有最终音频，需要字幕或动画的真实短语时间边界时，交给 `$cs-narration-phrase-timeline`。
- 用户要求完整自媒体剧本包或“口播附分镜分图提示词”时，本 Skill 完成口播后，在同一请求内交给 `$cs-chatcut-video-blueprint` 补齐逐镜分镜、逐图图片提示词和按需的动作提示词；沿用已定稿件与授权，不再次询问是否继续。
- 只要口播时保留本 Skill 的精简交付，不主动展开制作包。分镜与提示词由蓝图 Skill 负责；本 Skill 不负责选题池、项目操作、配音、音频对齐、剪辑、渲染、发布，也不虚构素材 ID 或最终时码。

## 完成检查

交付前确认稿件可独立朗读，表达标注没有混入台词，所有外部事实与用户经历都可回链到输入，且结尾没有为转化而强加 CTA。缺少关键事实时，明确保留待确认项，而非把稿件包装为已验证的完整故事。
