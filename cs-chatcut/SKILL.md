# ChatCut 视频策划与操作指南

把零散内容与视频想法收敛成明确受众、唯一核心观点和可组装的 ChatCut 制作蓝图，并提供从安装到导出成片的零到一操作指引。

## 边界与分工

- **严格保持策划边界**：不创建/修改 ChatCut 项目，不导入导出/渲染素材，不编写 Motion Graphics JSX，不调用 ChatCut MCP，不虚构 asset ID，不设计数字人外观/服装/表演（只通过口播稿和表达标注支持）。
- **准确术语**：动画视觉层称 **Motion Graphics**，区分 `透明叠加` 与 `全屏不透明`，时间安排锚定最终口播结构。
- **操作上手指引**：涉及安装 ChatCut Agent、首次建项目、从脚本到导出流程或排查上手问题时，查阅 [`references/zero-to-one-guide.html`](references/zero-to-one-guide.html)。
- **相近入口分工**：
  - 只需要自媒体剧本、逐镜分镜、逐图图片提示词与动作提示词：优先 `$cs-chatcut-video-blueprint`。
  - 电商对标复刻、九宫格、Seedance / Gemini Omni / Google Flow / Veo：使用 `$cs-auto-videl`。
  - 长文/公众号/改稿用 `$cs-writer`，外部事实调研用 `$cs-search-skill`（可接收其产物，不替代它们）。
  - 实际 ChatCut 项目操作与数字人产品视频流水线：确认蓝图后交接给对应编辑工作流或 `$cs-digital-human-product-video-pipeline`。

## 语言规则

默认简体中文输出所有提问、表格与交付物；保留 ChatCut、Motion Graphics、BGM、SFX、A-roll、B-roll、CTA、JSX、MCP 等标准技术词与必要英文原文，不因元数据字段切回英文。

## 三阶段工作流与输入门槛

不要在主题未定前要求完整视觉 brief，也不要因视觉素材未定阻塞口播稿。缺少信息时只追问当前阶段真正阻塞的字段；未证实事实标“待确认”，绝不编造。

### 阶段 A：内容与想法收敛（主题未锁定时）

- 单个想法：提炼目标受众、真实张力、可支撑事实和最小可拍形式。
- 一批想法：合并去重保留 3–5 个候选，按**受众相关性、观点张力、事实/素材支撑、制作可行性**（1–5 分）排序并给依据。
- 默认交付：**推荐主题 → 候选排序 → 内容切口（Hook 与不可承诺边界）→ 最小制作建议 → 下一步**，并暂停等待用户选定主题。

### 阶段 B：口播稿确认（第一轮交付）

必需信息：主题与目标、原始内容、发布平台、成片时长、目标受众与痛点、唯一核心观点、说话人身份与立场、语气节奏、CTA（或明确“无 CTA”）。

执行步骤：
1. 复述脚本 brief，分离已确认事实、用户观点、案例/数据与待确认项。
2. 锁定唯一核心观点与节拍骨架（默认 `Hook → 冲突/痛点 → 解释或证据 → 结论 → CTA`，服从内容逻辑）。
3. 写口语化初稿并做三项自检：事实可追溯、朗读自然度、观看推进；按实际可朗读字符数核算时长（不含标点/标注），偏差超 10% 须重写。
4. 按 [`references/planning-templates.md`](references/planning-templates.md) 输出**第一轮：口播稿确认版**，默认暂停等用户确认；仅当用户明确要求“端到端”时，完成第一轮质检后连续进入阶段 C。

### 阶段 C：完整制作蓝图（第二轮交付）

补充确认画幅比例、视觉/品牌约束、已有 A/B-roll 与截图、字幕要求、参考片及版权限制后，读取 [`references/planning-templates.md`](references/planning-templates.md) 按固定 6 节格式交付：

1. **制作策略**
2. **素材总清单**（`M01`…，仅要求支撑具体口播或镜头的素材）
3. **已确认口播稿与时间基准**（禁止静默改写）
4. **画面视觉与 Motion Graphics**（区分透明叠加/全屏不透明与安全区保护；高级动效补导演层）
5. **声音设计**（人声为 anchor、BGM 为 follower + 逐事件 SFX）
6. **逐镜头总表**（秒数覆盖计划时长，编号一致）

## 口播硬门槛

- 一句话只承担一个动作或观点；每个节拍必须推进新信息，不换说法重复。
- Hook 在前 2–3 秒直入结果、冲突、反常识或具体场景；禁用“今天我们来聊聊”等空开场。
- 统计、评价、保证、产品能力无依据时必须删掉或标“待确认”；保留说话人真实限定与判断。
- 纯口播与停顿/重音等表达标注必须分开，避免标注被配音误读。
- CTA 最多一个动作；交付前必须通过朗读自然度与模板里的质量检查清单。
