## Main Topic

本信息图说明 `cs-recover-skill` 如何识别 GPT-5.6 因过度追求单次成败而出现的执行失速，并通过四步复位流程恢复面向用户价值的推进。

## Learning Objectives

After viewing this infographic, the viewer should understand:

1. GPT-5.6 的“得失心过重”在任务执行中如何表现。
2. 如何用四步流程判断哪些验证值得做。
3. 何时应停止优化并交付或请求授权。

## Target Audience

- **Knowledge Level**: Intermediate
- **Context**: 需要快速理解技能功能、用于 GPT-5.6 任务复位的 AI 产品构建者。

- **Data Structure**: 问题信号 → 复位判断 → 收束动作 → 有效进展。
- **Key Relationships**: 每个功能信号都导向一次更少但更有价值的验证或行动。
- **Visual Opportunities**: 左侧故障信号模块、中央四步流水线、右侧交付出口与停止规则。

## Key Data Points (Verbatim)

- "反复推演、无效验证、扩张范围、迟迟不交付，或把工具调用本身当作进展。"
- "最大化用户的有效进展，而不是最大化单次回答的完美度。"
- "只有会改变决定的缺口才值得继续调查或调用工具。"
- "每次验证都必须有一个新假设和停止条件。"
- "满足用户明确需求、关键事实已验证、风险与假设已透明、后续仍可迭代。"
