# 发布前真人验收

静态检查只能检查结构、资源引用与场景数据的完整性，不能保证真实新会话中的路由、追问和交付质量。每个发布候选版本都复制最近的验收模板，例如 v0.6.0.md，使用**全新会话**逐项执行其中的 Prompt，并如实填入：

- 实际路由或动作；
- 关键输出或链接；
- 失败项与修复结论；
- 验收人和日期。

任一必填案例未通过时，不发布该版本。出现新的误路由、无意义追问、越权交付或不可用输出时，先把它加入 `tests/fixtures/routing-cases.json` 的行为案例，或为可执行脚本增加真实回归。不要用匹配某句话来证明模型做对了。
