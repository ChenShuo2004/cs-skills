# GPT 出图 × 代码动画

一句话：**GPT 负责画得好看，代码负责动起来、写得准。** 两边各做自己擅长的，合在一起才有完整的片子感。

## 一、别人是怎么做的（拆解）

### xilo《用 Claude 做 AI 梦核短片》（208 秒，约 65 个镜头，平均 3.2 秒一切）

两种镜头交替出现：

| | 插画镜头（约 1/3） | 讲解镜头（约 2/3） |
|---|---|---|
| 画面 | GPT 出的整张插画：主角在书桌、画架、剪辑台前做事 | 深色网格底 + 代码画的界面：对话框逐字打出、素材卡片弹入、大号步骤数字、绿色标签 |
| 动 | 慢推、慢移（Ken Burns），画面本身不动 | 卡片弹簧入场、选中高亮、箭头、进度条 |
| 角色 | 主角满幅出镜；一个**白模小人**当 AI 搭档（我们对应用 KAI 猫来演） | 左下角圆形头像，**三种嘴型跟着口播换**，旁边有说话线 |
| 字幕 | 黑底白字字幕条 | 白字无底 |

关键做法：

- 所有插画都用同一个角色设定生成，所以几十张图里主角长得一样
- 插画里不放文字，文字（步骤、标签、价格）全部由代码叠加，保证准确
- 讲解镜头里的「素材」也是图（截图、生成结果），代码只负责排版和动
- 镜头有编号（S001…），说明他是按分镜表批量生产的

### 你之前的 cs-skill 片（482 秒，19 页网页幻灯片 + 录屏）

- 好的地方：GPT 手绘插画 + 深色界面的组合已经对了，视觉有个人感
- 问题：一页停约 25 秒，节奏慢；录屏带着浏览器外框和鼠标；插画是静止的；没有角色在讲

**改法**：录屏换成 `render(t)` 直接渲染；插画加运镜；加 KAI 头像对口型；切镜控制在 3 秒左右。

## 二、分工：什么交给 GPT，什么交给代码

| 交给 GPT | 交给代码 |
|---|---|
| 场景插画、角色在场景里做事 | 运镜、转场、节奏 |
| 道具、素材卡里的内容 | 所有文字、数字、字幕、标签 |
| 头像的嘴型帧、表情帧 | 界面（对话框、卡片、进度条）、图表 |
| 封面底图 | 签名动作、3D 角色（kai-boy-3d / kai-cat-3d） |

判断规则：

- 要**准确的文字或数字** → 代码
- 要**质感、氛围、复杂的手绘** → GPT
- 要**动** → 代码
- 一张图既要质感又要文字 → GPT 出**无字底图**，代码叠字

## 三、镜头类型（layers.js 一行调用）

| 类型 | 用途 | 配方 |
|---|---|---|
| A 插画镜头 | 讲故事、交代情绪、开头和结尾 | `L.illustration(g, I.xxx, k, {from, to})` + `L.subtitle(..., {style:'box'})`；有分层图就用 `L.parallax` |
| B 讲解镜头 | 讲步骤、讲操作、讲数据 | `L.grid` + `L.promptBox` / `L.card` / `L.bigStep` + `L.avatar` + `L.subtitle` |
| C 角色镜头 | 签名动作、开场亮相、片尾 | `KaiBoy3D` / `KaiCat3D` 透明底叠加，或 GPT 出的角色立绘 + 弹簧 |

建议比例：A 30–40%，B 50–60%，C 每支片 1–3 次。一个镜头 2–4 秒。

## 四、生产流程

```
口播稿 → 分镜表（每镜：类型 / 时长 / 画面 / 用哪张图）→ assets.json
→ gen_image.py --dry-run（看要出多少张）→ --draft（快模型，每张 2 个候选）
→ 挑图（--pick id=序号）或 --final（精修模型）→ 代码合成 → qa.py
```

- 一支 2–3 分钟的片：插画 8–15 张 + 头像嘴型 1 条 + 素材卡按需
- 先出草稿挑方向，只给选中的出定稿
- 没有 API Key：`--export-md` 导出 prompts.md，在 ChatGPT 里逐张手动出，存成同名文件放进 `images/`，后面流程不变

## 五、保证角色一致

1. **每张图都带参考图**：`refs` 里放角色设定图（`assets/character/kai-boy-sheet.png`、KAI 猫原图），脚本自动用 `input_fidelity: high`
2. **风格提示词写死**：`assets.json` 的 `style` 字段整片共用，不要每张重写
3. **同一个场景出多个机位**：先出一张场景母图，再把母图当参考图出其它机位
4. **嘴型、表情一次出一条**：一张横图里并排画三格（闭嘴 / 半张 / 张大），再用 `split: 3` 切开。分开出会长得不一样
5. **尺寸统一**：插画 1536×1024（代码按 cover 裁成 16:9），竖版素材 1024×1536，头像条 1536×1024（三格横排）

## 六、成本闸门

- 每次真正出图前先跑 `--dry-run`，看清张数、模型、质量再确认
- 草稿默认 `gpt-image-2.5-flare` + medium，定稿默认 `gpt-image-2.5-sunburst` + high（2026-09 的模型名，变了用环境变量 `KAI_IMAGE_DRAFT_MODEL` / `KAI_IMAGE_FINAL_MODEL` 改）
- 同样的参数不会重复花钱（按参数哈希缓存）
- 价格以 OpenAI 官方价格页为准，不在这里写死

## 七、踩坑

- **GPT 图里的字会错**：一律不让它写字，提示词里明确「不要文字」
- **角色比例漂移**：每张都带参考图；漂了就把上一张满意的图也加进参考图
- **透明底边缘发白**：叠到深色底之前先单帧检查，有白边就改成浅色底的镜头
- **头像嘴型位置不齐**：三格必须同角度同大小；切开后叠在一起检查一遍
- **插画镜头太长会无聊**：超过 4 秒就加第二段运镜，或切到讲解镜头
