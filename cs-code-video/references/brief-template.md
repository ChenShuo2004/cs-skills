# brief.md 模板（7 块 XML）

用户选定风格卡、确认关键帧后，把下面 7 块全部填实写成 `brief.md`。它既是这支视频的制作依据，也是以后换主题、拿去别的工具跑的可复用提示词。用 XML 标签分块，是为了让模型分清要求、背景和示例，不容易混。

```xml
<role>
你是动态设计师兼创意程序员，擅长用代码做出有设计感的视频。
</role>

<inputs>
主题：……；看完要记住的一句话：……
系列 / 单片：……（系列写系列名，锁住它的皮肤）
核心冲突：从「……」到「……」
选中的隐喻：……（来自风格卡 A/B/C，或混搭说明）
时长 / 画幅 / 帧率：30 秒，1920×1080，30fps
风格：……（来自 director.md 风格库或新设计；参考视频只学手法）
配色与字体：底色 #……，主色 #……，信号色 #……；标题字体 ……，正文字体 ……，批注字体 ……
KAI 签名层：签名动作落在镜头 …；片头 ……；片尾 ……；声音标识 ……（signature.md 待定时写「暂不套用」）
声音：代码合成配乐 / 用户提供的音乐；配音：要（音色 zh-CN-YunxiNeural，语速 +4%）/ 不要
</inputs>

<direction>
一套风格一套配色，同一元素在每个镜头里长得一样。
每个镜头只讲一件事，字少而大，每段文字至少停 2.5 秒。
每个概念落到一个看得见的动作，动作的结构和概念的结构一样。
动画用缓动或弹簧，不用匀速。转场从内容里长出来（一条线变成下一场的地平线），不用默认淡入淡出。
镜头要推、拉、跟随，主体至少占画面三分之一。
禁止：居中大字 + 渐变背景的默认风格、深色底 + 黄字的模板配色（除非风格卡指定）、所有元素同时淡入、满屏小字、角落里多余的标签和边框、界面发光、组件渐变、弹跳缓动、粒子爆炸、任何像模板的东西；（本片补充）……
</direction>

<structure>
镜头 1｜0.0–3.0s｜类型：A 插画 / B 讲解 / C 角色｜图：s01_desk（GPT）或「代码画」｜画面：……｜动作：进场/主动作/出场｜镜头：推近｜声音：……｜转场：……
镜头 2｜……
标出签名动作所在的镜头。用到 GPT 图时，按 hybrid.md 把所有「图」整理成 assets.json。
有音乐时：镜头切换和关键动作落在拍点，重拍放最大的变化。
</structure>

<build>
代码路线：……（见 code-stack.md）
template.html 只用骨架；STYLE 和全部镜头按本 brief 重写。
window.render(t) 纯函数：不用计时器、CSS transition、requestAnimationFrame；随机数带种子；帧间不存状态。
scripts/render.mjs 逐帧渲染；scripts/audio.py 合成配乐与音效，音效时间点从画面关键帧抄；配音整段拼接，画面对旁白。
每做完一个镜头渲 3 张静帧自检。
</build>

<gotchas>
字体加载完才截图；WebGL 先渲一帧确认着色器生效；缩放元素和文字不加 will-change；
变形容器里的新旧文字各有进出场；循环片首尾帧完全一致；听不到声音就看波形图。
</gotchas>

<start>
按 structure 从第 1 个镜头做起，每个镜头自检通过再做下一个；全片渲完后按 qa.md 自评到每项 ≥8 分。
</start>
```

## 写 direction 禁止清单的要点

没有限制时，模型会回到它最熟的默认风格：深色背景、居中大字、所有东西淡入淡出。禁止清单写得越具体，出来的东西越不像模板。风格本身就要深色（CRT、夜景、霓虹）时照用，但排版和运动要有自己的设计。
