# Vibe 知识大赏模式：来源可核查的代码科普片

用户明确提出「Vibe 知识大赏」、来源可查的代码科普视频，或给出这类视频制作教程时，从 `$cs-code-video` 进入本模式。此文件覆盖主 skill 与它冲突的默认值；渲染、声音、逐镜制作和 QA 仍复用主 skill 的工具。参考教程的六段流程是：**搜集 → 编排 → 找图 → 定样式与分镜 → 检查 → 直出**。学习流程，不复制他人的文案、素材或画风。

## 与通用代码视频的差别

- 唯一阻塞输入是**知识主题或原材料**。若无其他指示，先声明可改的工作默认值：约 2 分钟、1920×1080、30 fps、无旁白、屏幕短句配音乐。用户指定竖屏、旁白、时长、品牌风格时以其要求为准。不要机械地重新问通用模式的五项输入。
- **允许并要求联网查证事实**，也可获取有使用权的真实证据图。通用模式的「事实只来自用户材料」「不从网上下载图片」在本模式不适用。
- 不强制加入 KAI 角色或通用签名层；用户明确选择 KAI 系列时才用。视觉从题目与证据中生长，不能先套暗夜星空或像素皮肤。
- 先做三张**可见的开头样图**，再写分镜；整片前先实际渲染开头 10 秒。用户已指定风格或授权自主完成时，记录选择并继续，不把常规制作关口变成多轮许可请求。
- 本模式的交付是事实证据与可重渲 MP4 的闭环。若用户只要提示词或分镜，则交到该阶段，准确报告状态。

## 交付结构

项目至少包含：

```text
sources.md         每条具体事实的来源、定位和核验状态
文章.md            查证后的知识材料
文案.md            按幕编号的屏幕短句、可选旁白和事实 ID
找图.md            每幕证据图的网址、截图范围、作者、许可与文件名
素材/              实际使用的图片和许可记录
风格样图/          三张开头样图及选择理由
分镜.md            逐镜时间、画面、字、素材、运动、转场、声音
brief.md           最终制作规格与画风约束
out/first10.mp4    开头 10 秒样片
out/final.mp4      完整成片
qa/                抽帧、解码、视觉检查记录
README.md          输入、依赖、重渲命令与核验结果
```

资料或素材没有取得时写明缺口，不用占位图冒充完成。源工程必须可重新渲染，不能只交 MP4。

## 1. 搜集：证据先于画面

把主题收束为观众会问的一个问题和一句核心结论。历史题可选 8–10 个节点，原理题可拆 5–8 个关键点；数量随内容调整。优先原始论文、机构、博物馆和官方档案，逐项核对年份、人名、数字、引语与因果关系。关键结论尽量用独立来源交叉核对；来源冲突时列明争议。`sources.md` 每行至少有事实 ID、拟呈现的说法、来源标题/机构、URL、页面定位、核验结论。没有可靠出处就删掉断言或改成有明确不确定性的表述。然后写 `文章.md`。

## 2. 编排：为观看写

`文案.md` 按幕列叙事目的、屏幕文字、可选旁白、预计阅读时长和事实 ID。第一秒尽快亮出具体问题或冲突，不以「考你一个问题」等套话铺垫。中段用至少一个生活比方；认知反转要有事实支撑；结尾说明与普通人有什么关系。无旁白时每屏原则上不超过 20 个汉字，专业词首次出现就用白话解释。用旁白时，屏幕字跟随旁白，不把整段口播贴上屏幕。

## 3. 找图：每张证据图可追溯

`找图.md` 逐幕列真实照片、档案、论文首页、原始图表、实物或自绘示意图的叙事作用、具体网址、需截取区域、作者/机构、许可与署名要求、目标文件名。优先公有领域或明确可用许可；**事实引用不等于取得图片使用权**，无法确认授权时自绘图解。用户明确要自己截图时，给精确截图清单，继续独立完成脚本与画风探索，素材到齐后再最终渲染。实际图像要融入画面设计，不能把网页截图原样铺满屏幕。

## 4. 定样式和分镜

同一开头幕制作三张视觉方案样图，差异应在构图、证据呈现、字体层级和运动逻辑上，不能只换颜色。可探索纪录片档案、编辑设计、课堂笔记等适合题目的方向；每张写一句适用理由。结合题目写 `avoid`，例如无意义霓虹、紫色渐变、字全堆在正中、全片只有淡入淡出。选定后写 `分镜.md`：镜号、起止秒、叙事目的、构图、屏幕文字、素材文件、运动、转场、事实 ID、声音。若有 BGM，可用 `python3 scripts/audio.py beats <音乐文件>` 测拍；主要切换尽量合拍，但不能牺牲阅读时间。完成后写入 `brief.md`。

## 5. 分镜检查

逐镜核对屏幕字是否读得完、年份人名数字是否与 `sources.md` 一致、素材许可是否清楚、安全区与字号是否适合手机观看、是否有拖沓空镜或重复转场。开头第一秒直接呈现问题或冲突。修好分镜再付正式渲染成本。

## 6. 先 10 秒，再整片

复用 `cs-code-video` 的 `render(t)` 工程和声音管线。先做一个可渲染镜头证明工具链能跑，再实际渲染 `out/first10.mp4`。检查 0、2、5 秒和末帧的字体、出框、重叠、错字、事实和声画同步；需要用户选风格或看样片时交付等待反馈，已授权全程自主制作时自评并继续。整片完成后运行 `python3 scripts/qa.py out/final.mp4 qa` 并人工查看抽帧，再运行 `python3 scripts/verify_video.py out/final.mp4 qa/verify` 记录 `ffprobe` 元数据、完整解码结果和首中末抽帧。核对时长、画幅、帧率和音轨。最终报告真实文件路径与检查结果，区分样片、完整渲染和已发布状态。

## 给 Claude Code 的启动提示词

```text
请使用 $cs-code-video 的 Vibe 知识模式（先读 references/vibe-knowledge.md），把「〔知识问题〕」做成约 2 分钟的代码科普视频。先联网查证事实并写 sources.md、文章.md、逐幕文案.md；为每幕列出真实证据图的地址、截图范围、作者和许可，无法确认使用权就改用自绘示意图。用同一开头做 3 张差异明显的真实风格样图，选定后写逐镜分镜并逐项检查年份、阅读时间、手机安全区与节奏。请在视觉约束中写明 avoid，先实际渲染前 10 秒 MP4 供我查看；满意后再制作完整 MP4，并交付所有素材、源工程、重渲命令及事实与视频 QA 记录。画幅〔横屏/竖屏〕，声音〔配乐/旁白〕。每个阶段准确标记已完成与待完成，不要把计划当成成片。
```
