# 一起完善案例库

过审是共建项目。大家运行技能，获得小红书、抖音、B站或视频号的实际反馈后，回到原对话提交结果。助手整理匿名案例，在获得公开授权后自动向本仓库创建修改提案（PR），维护者复核合并后进入真实案例库。

**运行技能 → 平台反馈 → 匿名回传 → 自动提交 PR → 复核入库 → 帮助下一次审核。**

## 怎样参与

1. 用技能检查视频，再自行到目标平台投稿、加热或申诉。技能不会替你发布视频，也不会自动读取平台账号结果。
2. 在原对话回传实际反馈：平台、日期、投稿或加热等环节、通过/拒审/申诉结果、通知原文、相关时间点、修改与重试过程。没有通知写明没有；未知原因保留未知。
3. 助手把反馈整理为匿名案例，先展示将公开的完整记录。原片、私人报告、账号信息、联系方式、密钥和本机路径不提交。
4. 确认记录准确、有权公开并授权提交。若已经明确授权这份具体记录，助手直接继续，不重复询问。
5. 助手校验案例格式、创建独立分支并自动向 `huangbai-AI/guoshen` 提交 PR，返回可打开的提案链接。你不必自己填写 JSON 或手动提交文件。
6. 维护者复核事实、匿名化与适用场景，合并后案例进入 `cases/records/`。下一次审核可读取同平台、同场景的真实案例，帮助分析，也保留通过与申诉反例。

可以这样回传：

> 这是上次视频在抖音的实际反馈。请整理匿名案例给我确认，确认后自动提交到 guoshen，完善案例库。

也可一次提供已匿名的具体记录，并明确“我有权公开这些内容，授权自动提交案例 PR”。授权仅覆盖这份记录，不包含原视频或其他私下材料。

## 自动提交需要什么

运行技能的助手需要可用的 Git、GitHub CLI（`gh`）、GitHub 登录和网络。写权限可直接使用独立分支；没有仓库写权限时，使用贡献者自己的仓库副本（fork）提交。不要要求贡献者把访问令牌贴进对话。

这些操作由运行技能的助手执行，并非仓库后台自动监听平台。环境缺少依赖或登录失败时，助手保留整理好的记录，说明阻塞原因；完成登录后继续提交。没有取得 PR 链接并核对新增文件前，不声称已经回传成功。也可通过 [案例表单](https://github.com/huangbai-AI/guoshen/issues/new?template=case.yml) 手动贡献，但表单本身不会自动生成 PR。

## 案例怎样入库

- 真实反馈使用 [案例格式](../resources/schemas/case.schema.json)，标记 `synthetic: false`，保存到 `cases/records/CASE-XXXX.json`。
- `cases/examples/` 继续存放模拟填写示例，不能把模拟反馈当真实结果。
- 每个平台或发布环节分别记录。事实、平台通知、AI假设、修改重试与其他影响因素分开，不凭“删掉后通过”就确认拒审原因。
- 先检索自己的既有案例与未合并 PR；同一事件的后续反馈优先更新同一案例，避免重复提交。不能覆盖别人的记录。
- 校验通过只表示结构符合要求；维护者仍需核实证据与公开授权。
- 案例不会自动更改生效规则。规则修订继续按 [版本治理](rule-lifecycle.md) 另行复核。
