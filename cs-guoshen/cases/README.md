# 案例区

欢迎提交拒审、通过、申诉成功和前后结果发生变化的记录。目标是发现可复核的共性，也保留反例。当前 [examples](examples) 中5份都是模拟示例，**没有真实平台实测结论**；[records](records) 尚无真实公开案例。

## 运行技能后回传

大家运行技能并拿到平台实际反馈后，可以回到原对话回传结果。助手整理匿名案例并展示待公开记录；获得对该记录的公开授权后，自动向本仓库创建 PR。维护者复核合并后进入真实案例库，帮助下一次审核。操作条件与步骤见 [共建流程](../docs/community.md)。通过、拒审和申诉结果都欢迎；同一事件的后续反馈优先更新原案例。

## 填写与提交

通过 [案例表单](https://github.com/huangbai-AI/guoshen/issues/new?template=case.yml) 提交，或复制 [模拟示例](examples/EX-0001.json)，按 [案例格式](../resources/schemas/case.schema.json) 新建 `records/CASE-0001.json` 并提 PR。编号冲突时选下一个空号；真实记录设 `synthetic: false`。

必须分别记录：平台与失败环节、提交日期、平台通知原文（没有写 null）、证据通道与时间、AI假设、已确认原因、每次修改和重试、其他影响因素、关联规则。日期不清时先通过问题表单说明，勿为满足格式编造日期。

`confirmed_reason` 仅填写平台明确反馈能支持的具体原因；通用“违反规范”不支持自填“网址违规”。`attempts` 按时间顺序填写，每次写日期、变更和结果；没有重试时留空数组。跨月结果变化同时记录内容版本、账号条件、发布入口和通知差异，不能仅凭月份断言规则已改变。

## 公开前检查

仅提交有权公开的匿名内容；删除姓名、账号标识、私人路径、联系方式、访问令牌、未授权人物及素材。遮挡后检查文件元数据与字幕，不把原件遗留在提交记录中。公开视频也不等于可重新分发其全部素材。不要上传整条私人原片；通常通知文字、必要匿名片段和时间点已经够分析。

格式里的公开授权与匿名化勾选是贡献者声明，维护者仍需人工核查。用户把视频交给助手私下审核，不等于授权公开。发生误传请联系维护者处理，不能假定关闭问题就会消除已公开副本。

## 从案例提炼共性

按同平台、同场景、相近日期、可比版本分组，同时收集成功及申诉反例。报告样本来源与选择偏差；不要用零散自选样本计算平台真实通过率。候选结论先进入 [insights](insights)，经复核后按 [版本治理](../docs/rule-lifecycle.md) 提规则 PR，不自动生效。
