# 有温度 IP

## 核心目标

生成、修改或延展“有温度”IP 时，始终执行：**换动作、换场景、换媒介，可以；换掉角色身份，不可以。**

角色 DNA 优先级高于画风。不要把角色改成普通梨子、鸡蛋、水滴、动物或通用萌物。

## 先读参考

按任务读取，不要一次加载全部文件：

- 首次生成、角色修复、三视图或一致性任务：读取 [references/character-dna.md](references/character-dna.md)。
- 2D、3D、黑白、联名、动作、表情或多形态延展：读取 [references/media-and-variants.md](references/media-and-variants.md)。
- 准备生图或编辑提示词：读取 [references/prompt-templates.md](references/prompt-templates.md)。
- 每次交付前：读取 [references/qa-checklist.md](references/qa-checklist.md)。
- 需要视觉锚点时：查看 [assets/reference-ip.png](assets/reference-ip.png)。示例图只用于校准身份和完成度，不得当成固定构图模板。

## 任务分类

先判断任务属于哪一类：

1. **角色延展**：保持身份，改变动作、表情、场景或构图。
2. **媒介转换**：保持结构，将 2D 转成 3D、线稿、软胶、树脂等媒介。
3. **风格迁移**：图一负责角色和构图，图二只提供线条、材质、色彩或氛围。
4. **联名共创**：让多个角色属于同一画面语言，但不能互相复制身体轮廓和标志元素。
5. **角色修复**：找出丢失的 DNA，优先修复轮廓、爱心天线、面部和四肢。

如果任务涉及信息图、结构图、海报或复杂叙事，先从“定义、流程、对比、层级、因果、清单、时间、矩阵”中选择一个主结构，再设计画面。不要未经结构判断直接生图。

## 不可变身份锚点

每张图至少保持这些要素：

- 不规则、微倾斜的暖黄色“温度种子”软团；左下略鼓、右上略收，避免标准对称形。
- 一根细长、略弯的顶部天线，末端为暖橙色空心爱心轮廓。
- 两只间距偏宽的黑色纵向椭圆眼睛、极简小弧线嘴、淡橙色腮红；不画鼻子。
- 极细黑色线状四肢，末端极简；默认不加鞋、手套或人类手掌细节。
- 暖黄主体、墨黑五官四肢、少量暖橙点缀；避免荧光色和彩虹配色。

手持“连接爱心”可随场景移除，但连接、传递、点亮、陪伴或品牌说明场景优先保留。

## 工作流

### 1. 锁定输入角色

把角色参考图标记为“身份参考”，把其他图片明确标记为“风格参考”“场景参考”或“编辑目标”。不要默认所有输入图都是编辑目标。

### 2. 写出不变量与变量

生成前列出：

- 不变量：轮廓逻辑、爱心天线、面部比例、细四肢、暖色体系。
- 变量：动作、表情、场景、构图、媒介、光线和画法。

### 3. 设计品牌动作

优先让角色执行一个有意义的动作：连接一个人、点亮一个物体、递出有价值的东西、陪伴别人完成一步行动。不要只站着卖萌。

### 4. 单张生成

用户明确要求生成时，直接调用可用的图像生成工具，不停在提示词阶段。每个独立资产单独生成，不把多张需求拼在一张图里。

默认使用 2D 手绘蜡笔 / 油画棒 / 彩铅混合质感和暖白背景。用户明确要求 3D、黑白或其他媒介时，再切换对应规则。

### 5. 检查与迭代

按 QA 清单检查。若身份锚点有两项以上失败，重新设计，不要继续小修小补。若只有一个局部问题，做单一目标编辑并重复写明不变量。

### 6. 保存交付

项目内资产保存到用户指定目录；未指定时使用清晰、可排序的文件名。不要覆盖旧资产，除非用户明确要求替换。交付时报告用途、路径、媒介和仍需注意的漂移风险。

## 用户指令优先级

- “只换颜色” → 不改形。
- “只换风格” → 不改角色结构。
- “图一换成图二风格” → 图一负责角色与构图，图二只负责视觉语言。
- “做三维图” → 保持结构，只转换体积、材质和光线。
- “多来几个不同的” → 改变轮廓比例、重心、凹凸与肢体位置，不能只换材质。
- “和另一个 IP 共创” → 同世界观、不同角色 DNA。

如果参考图与角色 DNA 冲突，以用户当前明确指令和已确认的角色身份为最高优先级。
