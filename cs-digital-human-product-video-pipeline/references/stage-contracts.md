# 七阶段合同与审批闸门

已有有效原声或数字人素材可满足对应阶段输出；验证来源与输入版本后复用，不要求运行原生成服务。仍需检查同步、身份、音频质量与最终合成。阶段验收按 product-pack 指定规格与声音政策执行，表中的无 BGM 是默认规格。

| 阶段 | 输入 | 必须产出 | 通过闸门 | 不通过时 |
| --- | --- | --- | --- | --- |
| 1. 选题/事实 | 产品包、参考视频、真实素材 | 事实矩阵、禁用断言、参考分析、素材清单 | 每个主张都有证据或被标记待确认 | 删除/改写无证据断言，不补造能力 |
| 2. 口播 | 已确认事实、目标时长、CTA | 可朗读脚本、段落时间预算、证据映射 | 一个核心观点；每段有对应画面 | 回到事实或脚本，重新确认改动 |
| 3. 配音 | 锁定脚本、授权声音配置或原声 | 最终旁白、真实对齐数据、可懂度检查 | 授权可追溯；无削波；时码来自实际音频 | 停止并请求授权/重新录制/重新生成 |
| 4. 数字人 | 最终旁白、通过预检的本地工作流 | 数字人片段、动作/背景记录、渲染引用 | 同步可用；人物不遮挡关键构图 | 修正工作流或停止，不能用未批准替代品 |
| 5. 产品场景 | 事实矩阵、UI/组件素材、脚本 | 证据型 B-roll、镜头清单、素材引用 | 每段口播均有事实相关画面 | 补产品素材或缩减脚本断言 |
| 6. ChatCut 编辑 | 音频、数字人、产品场景、时间基准 | 锁定剪辑基底、字幕、转场、SFX、项目结构截图 | 素材去重；字幕校正；无 BGM | 在 ChatCut 修复，不能只靠导出掩盖 |
| 7. Remotion 包装与成片 | 锁定剪辑基底、真实时码、品牌参数 | 包装合成、最终导出、QA 报告 | 合成帧、编码、时长、音频与事实 QA 均通过 | 回到对应阶段修复后重验 |

## 阶段 1：参考视频分析

参考视频只可以提供：

- 段落时长与信息密度；
- Hook、承诺、演示、总结、CTA 的结构；
- 镜头变化、字幕密度、转场强度和能量曲线；
- 不同画面类型与口播句子的对应关系。

不要复制它的脚本、镜头、人物、产品 UI、音乐、素材、品牌识别或逐帧动作。分析结论必须和本产品的真实事实分开记录。

## 阶段 2–5：事实优先

每一句口播都应有以下映射：

~~~
口播段落 → claim id / 用户确认事实 → evidence asset id → 画面任务 → 字幕关键词
~~~

如果只有抽象愿景而没有证据，使用经用户确认的限定表达，或删去该段；不要伪装成已实现功能。

## 阶段 6：剪辑真相源

ChatCut 项目记录主口播、字幕、产品证据、PIP、转场和 SFX 的真实编排。每次修改前检查已有素材及轨道，避免重复导入。组件原声如果与主口播冲突，应只作为低音量或静音的事实画面，不抢占解释主线。

## 阶段 7：确定性包装

Remotion 输入必须包含锁定剪辑的版本、章节边界、时码、包装文本和产品包快照。它只能做可重复的介绍页、章节、进度、CTA 和最终组合；不要重新解释或更改已经锁定的产品事实。

## 审批记录

样片审查看三件事：

1. 产品事实、口播、字幕和 UI 是否一致；
2. 数字人、圆形 PIP、转场、SFX 与产品界面是否协调；
3. 规格、节奏和 CTA 是否足以进入完整生产。

仅以下明确记录允许进入 batch：

~~~text
sampleStatus: approved
approvedBy: user
approvedAt: ISO-8601 timestamp
approvedPackRevision: immutable product-pack snapshot id
~~~

其他状态 pending、changes-requested、not-reviewed 一律停止在样片阶段。
